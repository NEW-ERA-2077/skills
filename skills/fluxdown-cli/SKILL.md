# FluxDown — скачивание и управление задачами через CLI

## Назначение и среда

- Работай **через локальную команду `fluxdown`**, не через MCP и не через самостоятельно собранные запросы `curl`: CLI уже оборачивает API.
- Целевая система: Windows, CMD или PowerShell. Пользователь ранее проверил подключение к **FluxDown 0.6.0** и получил ответ `pong`; всё же не считай это гарантией текущего состояния службы.
- CLI установлен на компьютере пользователя и вызывается по имени `fluxdown`. Известный каталог установки: `C:\Users\user\AppData\Local\Programs\FluxDown\`. Если команда перестала находиться, проверь `where fluxdown` (CMD) / `Get-Command fluxdown` (PowerShell), затем путь к исполняемому файлу. **Не перезаписывай основной исполняемый файл приложения.**
- По умолчанию CLI подключается к приложению по `http://127.0.0.1:17800`. Приложение должно быть запущено, локальный API включён.
- Ключ доступа НЕ храни в навыке, скриптах, исходном коде или журналах. Получай его из `FLUXDOWN_TOKEN` либо настроенного пользователем CLI-конфига. Если не настроено, объясни первоначальную настройку из раздела ниже. Не распечатывай значение ключа командой `config get token`.

## Первоначальная настройка API и токена (включая отсутствие токена)

Этот раздел обязателен, если `fluxdown ping` сработал, а `fluxdown --json list` сообщает об ошибке авторизации, если CLI запущен впервые или если API выключен. **Ответ `pong` не означает, что авторизация настроена**: `ping` не требует ключа.

1. Убедись, что настольная программа FluxDown запущена. Проверь `fluxdown ping`. Если связи нет, попроси запустить приложение и проверь порт в интерфейсе; стандартный адрес `http://127.0.0.1:17800`.
2. В настольном FluxDown открой **Settings (Настройки) → API Service (Служба API)**. Убедись, что **Enable API Service** включён и включи **Management API** (изначально выключен). Это необходимые переключатели для удалённого режима CLI.
3. Найди поле **Access Token (Ключ доступа)**. Если ключ пустой, **создай его кнопкой генерации** рядом с полем; если ключ уже существует — **скопируй** его кнопкой рядом с полем. Ключ нельзя получить из `ping`, вывести из адреса или придумать самостоятельно, не изменяя настроек приложения. Если агент работает только через терминал и ключ недоступен, **дай пользователю эти действия в интерфейсе** вместо попыток обойти авторизацию.
4. Настрой один из вариантов в **CMD Windows** (подставь полученный ключ вместо `ВАШ_КЛЮЧ`, не сохраняй само значение в SKILL.md):
   ```cmd
   fluxdown config set token "ВАШ_КЛЮЧ"
   fluxdown --json list
   ```
   Ключ сохранится в локальной конфигурации CLI **открытым текстом**. Если пользователь не хочет постоянного хранения, доступна команда **только на один вызов** `fluxdown --token "ВАШ_КЛЮЧ" --json list`; или переменная только текущего окна CMD: `set "FLUXDOWN_TOKEN=ВАШ_КЛЮЧ"` и далее `fluxdown --json list`. В PowerShell временно: `$env:FLUXDOWN_TOKEN = 'ВАШ_КЛЮЧ'`. Вариант с аргументом/переменной может оставить ключ в истории команд или журналах; по возможности вводи его только в доверенной локальной среде.
5. После настройки **обязательно** проверь `fluxdown --json list`. Если задача отрабатывает без ошибки авторизации — готово, можно выполнять `add`, `status`, `watch` и другие команды без повторной передачи токена.
6. Если ошибка остаётся: код завершения `24` — проверь наличие и правильность ключа и включение **Management API**; код `5` — связь/адрес/порт/запуск FluxDown. Не генерируй и не меняй существующий ключ без явного согласия пользователя: это может нарушить другие интеграции. Не печатай ключ при диагностике.

Если пользователь не хочет настраивать API/токен, **для отдельного скачивания** возможен независимый режим `fluxdown add "URL" --local --dir "D:\Downloads"`: он не обращается к API, не нуждается в ключе и сам скачивает файл. **Он не управляет очередями настольного FluxDown** (`list`, `status`, `pause`, `resume` в этом режиме недоступны). Не запускай автономный движок с тем же каталогом данных, который уже используется работающим экземпляром приложения.

Документация: https://fluxdown.zerx.dev/docs/en/getting-started/settings/ и https://fluxdown.zerx.dev/docs/en/api/cli/ .

## Алгоритм агента

1. Определи вход: один URL / несколько URL / файл со ссылками / идентификатор существующей задачи; каталог и имя нужны только если названы пользователем. Ссылки не изменяй, не удаляй параметры `?`, `&`, `=`.
2. Если связь ещё не проверена в текущей сессии или есть сбой, выполни `fluxdown ping` и при необходимости `fluxdown info` / `fluxdown --json list`. `ping` **не проверяет ключ**, проверяй авторизацию через `list`.
3. Перед повторной загрузкой проверь уже известные задачи через `fluxdown --json list` (при доступности сведений сопоставляй полный URL, а также каталог/имя). Задачу с тем же URL в состоянии загрузки не дублируй; завершённый файл при наличии на диске используй повторно, если пользователь не попросил скачать заново.
4. Создай задачу через `fluxdown --json add ...`. Для заданного каталога укажи `--dir`, для имени **единственного** файла — `--out`; для нескольких URL обычно используй `--input-file` либо несколько позиционных аргументов.
5. Проверь код выхода команды и прочитай новые идентификаторы. **Создание задания не означает завершение скачивания.** При нескольких URL успех может быть частичным — сверяй результат для каждого URL.
6. Когда результат нужен для следующего шага (монтаж, анализ, обработка), проверь `fluxdown --json status <ID>` до состояния `completed`, либо используй `fluxdown watch <ID> --interval 2` с разумным ограничением времени исполнения. Проверяй `error`, зависание, сетевые ошибки; не запускай бесконечные циклы.
7. Для передачи файла другому инструменту определи **фактический** конечный путь из сведений о задаче и файловой системы. Если путь или наличие не подтверждены, сообщи это явно. Не подставляй наугад `%USERPROFILE%\Downloads`.
8. В ответе по умолчанию укажи кратко: файл/задание, состояние, подтверждённый путь; при ошибке — что не удалось и что делать дальше.

## Команды для обычной работы

Все глобальные параметры (`--json`, `--url`, `--token`, `--timeout`) ставь **перед** подкомандой. Параметры конкретной команды — после неё.

```cmd
fluxdown ping
fluxdown info
fluxdown --json list
fluxdown --json list --status downloading
fluxdown --json add "https://example.com/file.zip"
fluxdown --json add "https://example.com/file.zip" --dir "D:\Downloads" --out "file.zip"
fluxdown --json add --input-file "D:\Jobs\urls.txt" --dir "D:\Downloads"
fluxdown --json status TASK_ID
fluxdown watch TASK_ID --interval 2
fluxdown pause TASK_ID
fluxdown resume TASK_ID
fluxdown queue
```

**Windows и специальные символы:** В CMD URL с `&` передавай **целиком в двойных кавычках**: `fluxdown add "https://site.test/a.jpg?x=1&y=2"`. В PowerShell допустимы одинарные кавычки вокруг URL. Для множества сложных ссылок надёжнее `--input-file` (одна ссылка на строку). Не используй экранирование JSON из примеров `curl`: CLI принимает обычный URL.

**Необратимые действия:** `fluxdown rm TASK_ID` удаляет запись задачи; `fluxdown rm TASK_ID --delete-files` также удаляет файлы. Не вызывай `rm`, `--delete-files`, `pause-all`, `resume-all` без явного намерения пользователя; перед удалением файлов запрашивай подтверждение.

## Выбор режима

- **Обычный режим (предпочтительно):** `fluxdown add ...`; работает через уже запущенный FluxDown, задания видны в его интерфейсе.
- **Самостоятельная загрузка:** `fluxdown add "URL" --local --dir "D:\Downloads"` запускает встроенный движок без запущенного приложения/API/токена. Команда блокирует выполнение до завершения или ошибки. Используй по явному запросу либо если основной режим недоступен и это соответствует задаче; другие команды (`list`, `status`, `pause` и др.) всё равно требуют сервер. Это **не** загрузка без интернета.
- Для работы со ссылками, требующими авторизации, есть `--cookies`, `--referrer`, `--user-agent`, `--proxy`; не выдумывай сессионные данные и не выводи их в логи.
- Обычная веб-страница не равнозначна прямой ссылке на файл. Если сайт не поддерживается, объясни ограничение вместо ложного сообщения об успешной загрузке.
