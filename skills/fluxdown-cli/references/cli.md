# FluxDown CLI — подробный справочник для агента

Источники: официальная документация https://fluxdown.zerx.dev/docs/en/api/cli/ и описание API https://fluxdown.zerx.dev/docs/en/api/overview/ (проверено 2026-10-22). Ориентир: FluxDown 0.6.0 пользователя; при расхождении версии пользуйся `fluxdown --help` и `fluxdown <команда> --help`.

## Настройка доступа

### Где взять ключ и что делать, если его нет

На **настольном FluxDown** открой `Settings → API Service` (Настройки → Служба API). Включи **Enable API Service**, затем **Management API**. В поле **Access Token** нажми генерацию ключа, если оно пустое; иначе скопируй уже заданный ключ. Это ключ от самой программы, а не от сайта, с которого скачивается файл. Клиент CLI использует тот же ключ для управления заданиями.

Если задача только через терминал и ключ неизвестен, агент **не может извлечь/создать ключ CLI-командой**: инструкции пользователю по интерфейсу — обязательный шаг. **`ping` проходит без ключа**, а для проверки авторизации запускай `fluxdown --json list`. Не проси пользователя вставлять ключ в общедоступные журналы или в репозиторий. Нельзя менять действующий ключ без согласия — это может отключить другие приложения.

Для первичной настройки на Windows:

```cmd
fluxdown config set token "ВАШ_КЛЮЧ"
fluxdown --json list
```

Для проверки без сохранения (один вызов):

```cmd
fluxdown --token "ВАШ_КЛЮЧ" --json list
```

Для переменной окружения в **текущем CMD**: `set "FLUXDOWN_TOKEN=ВАШ_КЛЮЧ"`; в **PowerShell**: `$env:FLUXDOWN_TOKEN = 'ВАШ_КЛЮЧ'`. При запуске в терминале значение ключа может попасть в историю или журналы. После настройки не показывай значение командой `config get token`/`config list` и не добавляй в `SKILL.md`.

Без API и токена только для одиночной загрузки доступен `fluxdown add "URL" --local --dir "D:\Downloads"`; он запускает свой движок и **не управляет заданиями работающего приложения**. Не используй один и тот же каталог данных у одновременно запущенных движков. Подробнее см. раздел «О самостоятельном режиме» ниже.

```cmd
fluxdown ping
fluxdown info
fluxdown config path
fluxdown config set token <ВАШ_КЛЮЧ>
fluxdown config set url http://127.0.0.1:17800
fluxdown config set timeout 60
fluxdown config unset token
```

- Адрес по умолчанию: `http://127.0.0.1:17800`.
- Поддерживается переменная `FLUXDOWN_TOKEN` и `FLUXDOWN_URL`.
- Приоритет: явные флаги > переменные окружения > сохранённый конфиг > встроенные значения.
- Альтернатива без сохранения: `fluxdown --token <КЛЮЧ> --json list` (ключ может попасть в историю терминала или журнал процесса).
- `ping` не требует авторизации: его успех не свидетельствует о корректном ключе; команда `list` проверяет полноценный доступ.
- Конфигурация сохраняется открытым текстом в `%APPDATA%\zerx\fluxdown\config\cli.toml`; не публикуй её.
- Избегай выводить `config list` и `config get token` в открытых журналах — они могут показать ключ.

## Таблица команд

| Команда | Назначение |
|---|---|
| `ping` | Проверить доступность службы; без токена |
| `info` | Название и версия запущенного приложения |
| `add URL...` (также `get`) | Поставить одну или несколько загрузок |
| `list` (также `ls`) | Получить задания, возможно с фильтром |
| `status ID` (также `stat`) | Подробные сведения об одной задаче |
| `watch [ID]` | Наблюдать за загрузками до завершения/ошибки |
| `pause ID` / `resume ID` | Приостановить / возобновить |
| `rm ID` | Удалить запись задачи |
| `pause-all` / `resume-all` | Изменить состояние всех задач |
| `queue` | Показать настроенные очереди |
| `config set/get/unset/list/path` | Управлять локальной конфигурацией CLI |

Глобальные флаги (до подкоманды):
- `--url URL`, `--token TOKEN`, `--timeout SECONDS`, `--json`.

## Добавление загрузок

```cmd
fluxdown --json add "https://example.com/file.zip"
fluxdown --json add "https://example.com/1.jpg" "https://example.com/2.jpg"
fluxdown --json add --input-file "D:\Work\urls.txt" --dir "D:\Work\assets"
fluxdown --json add "https://example.com/video.mp4" --dir "D:\Videos" --out "clip-01.mp4" --segments 0
fluxdown --json add "https://example.com/file.zip" --checksum "sha256=0123456789abcdef..."
```

Параметры `add`:
- `-i, --input-file <PATH>` — файл ссылок по одной на строку; пустые строки и строки с `#` игнорируются; `-` = стандартный ввод.
- `-d, --dir <DIR>` — папка сохранения; без него применяется папка по умолчанию из FluxDown.
- `-o, --out <FILENAME>` — имя результирующего файла; действует только для **одного** URL; каталог задаётся отдельно.
- `-s, --segments <N>` — число сегментов, `0` = автоматически.
- `--proxy <URL>` — прокси конкретной задачи.
- `-U, --user-agent <STRING>` — строка User-Agent.
- `--referrer <URL>` — заголовок Referer.
- `--cookies <STRING>` — строка cookies для сайта.
- `--queue <ID>` — идентификатор очереди, если нужно.
- `--checksum <algo=hexhash>` — контрольная сумма файла, например `sha256=<реальный_хеш>`.
- `--local` — прямое скачивание CLI без API/токена; **только** у `add`.

Имя, переданное через `--out`, очищается от `..` и разделителей пути. Не пытайся выбрать папку через имя файла, используй `--dir`.

Успешный `add` возвращает новый ID (в обычном виде `added <id>`, в `--json` — массив идентификаторов). При нескольких URL некоторые могут быть добавлены, другие — отклонены. Не путай завершение *создания задач* с завершением *скачивания файлов*.

## Мониторинг, статусы, результат

```cmd
fluxdown --json list
fluxdown --json list --status pending
fluxdown --json list --status completed
fluxdown --json list --status error
fluxdown --json status TASK_ID
fluxdown watch TASK_ID --interval 2
```

Статусы фильтра `list --status`:

| Название | Код | Смысл |
|---|---|---|
| `pending` | 0 | ожидает |
| `downloading` | 1 | загружается |
| `paused` | 2 | приостановлено |
| `completed` | 3 | завершено |
| `error` | 4 | ошибка |
| `preparing` | 5 | подготовка |

`--json list` возвращает записи `TaskDto` с полями в camelCase; не предполагай заранее структуру, исследуй фактический JSON ответа установленной версии. При передаче файла следующему инструменту убедись, что файл существует на диске и что его путь определён из достоверных данных. Даже `completed` не заменяет проверку диска, если файл мог быть перемещён.

`watch` опрашивает состояние до завершения/ошибки и обновляет экран; `--interval 2` = интервал 2 секунды. При больших файлах не оставляй вызов без ограничения времени, если агенту нужны только постановка задачи и ID.

## Управление заданиями

```cmd
fluxdown pause TASK_ID
fluxdown resume TASK_ID
fluxdown rm TASK_ID
fluxdown rm TASK_ID --delete-files
fluxdown pause-all
fluxdown resume-all
fluxdown queue
```

- `rm` удаляет запись задачи; `rm --delete-files` также удаляет файлы на диске. Запрашивай подтверждение перед удалением файлов.
- `pause-all`/`resume-all` влияют на другие задачи пользователя; выполняй только при явном запросе.
- CLI не предоставляет все функции графической программы (например, настройку RSS через CLI); если функции нет в `--help`, не придумывай флаг или подкоманду.

## Коды завершения

| Код | Что означает | Реакция |
|---|---|---|
| `0` | успех | продолжить проверку состояния задачи |
| `1` | неизвестная ошибка | прочитать stderr; проверить синтаксис/ответ |
| `2` | истекло время или не задана команда | проверить доступность службы и параметры |
| `3` | задача не найдена | перечитать список, не повторять ID наугад |
| `5` | ошибка сети/нет связи с сервером | проверить, запущен ли FluxDown; `ping` |
| `7` | `--local` прерван, загрузки не завершены | сообщить, что загрузка неполная |
| `24` | не прошла авторизация | проверить локально заданный ключ/настройки API |
| `32` | неверный запрос/аргумент | проверить точный синтаксис команды |

Допускается ограниченное число повторных попыток **после выявления причины**; повторение `add` может создать дубликаты. На `401/403` не пытайся обходить авторизацию; запрашивай действительные параметры. Для ссылок с истекшим сроком действия нужна новая ссылка.

## CMD и PowerShell: особенности цитирования

CMD:
```cmd
fluxdown --json add "https://images.pexels.com/photos/30596214/pexels-photo-30596214.jpeg?cs=srgb&dl=pexels-zelch-30596214.jpg&fm=jpg" --dir "D:\Media" --out "pexels-zelch-30596214.jpg"
```

PowerShell:
```powershell
fluxdown --json add 'https://images.pexels.com/photos/30596214/pexels-photo-30596214.jpeg?cs=srgb&dl=pexels-zelch-30596214.jpg&fm=jpg' --dir 'D:\Media' --out 'pexels-zelch-30596214.jpg'
```

- В CMD двойные кавычки защищают `&` в аргументе URL от интерпретации как разделителя команд; не вставляй `\"` из примеров JSON/curl.
- Для произвольных/длинных URL или большого пакета предпочти `--input-file` и путь в кавычках.
- В CMD после команды доступен `%ERRORLEVEL%`; в PowerShell — `$LASTEXITCODE`. Не делай вывод об успехе только по напечатанному идентификатору без разбора ошибок.

## О самостоятельном режиме `--local`

`fluxdown add "URL" --local` выполняет загрузку до конца самостоятельно (без запущенного FluxDown и без ключа). Папка выбирается по приоритету `--dir` > сохранённая папка по умолчанию > текущий каталог. Для потокового HLS выбирается максимальный поток, для торрентов/magnet скачиваются все файлы — учитывай расходы диска и трафика. База задач может быть общей с настольной программой, если одинаковый каталог данных; у переносных установок каталоги могут отличаться. Другие подкоманды `--local` **не поддерживают**.

## Границы возможностей

CLI загружает по поддерживаемым URL и протоколам движка FluxDown. Это не универсальный извлекатель содержимого с произвольных веб-страниц; авторизация или ограничение доступа сайта могут мешать скачиванию. Не скачивай содержимое, на которое пользователь не имеет прав, и не отключай защиту/безопасность системы ради скачивания.
