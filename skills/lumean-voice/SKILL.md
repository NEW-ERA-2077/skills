# Lumean Voice — правила работы агента

## 1. Назначение и приоритет правил

Этот навык управляет **озвучкой уже подготовленных текстов** через API Lumean. Он не создаёт и не редактирует сценарии. Предпочтительный поставщик пользователя — ElevenLabs; также допускается Fish Audio **и любой другой поставщик/модель синтеза речи, реально доступный в Lumean на момент заказа**. Не ограничивай перечень исторически известными моделями и не выдумывай доступность.

**Приоритет:** конкретные правила этого навыка определяют рабочий процесс и решения, которые принимает пользователь; актуальная документация Lumean определяет действительные адреса запросов, поля, статусы, ограничения, расценки и способы скачивания. При расхождении технических возможностей с планом не имитируй успешное выполнение: опирайся на документацию и сообщай о препятствии в согласованное время.

**Не используй API ElevenLabs/Fish Audio напрямую.** Все заказы создаются только через Lumean. Устанавливать отдельный навык ElevenLabs не требуется.

## 2. Обязательное чтение документации (без переписывания API)

Перед первым обращением к API в текущей работе:

1. Прочитай **https://lumean.app/llms.txt** — карту документации и предупреждения для ИИ.
2. Прочитай страницу для агентов **https://lumean.app/developers/docs/agents** и прежде всего её правила и типичные ошибки.
3. Используй **https://api.lumean.app/docs/llm.md** как целостное русскоязычное описание API, если нужен полный контекст или сквозной пример. В случае большого объёма читай только необходимые разделы.
4. Для конкретного действия из `llms.txt` переходи к **актуальной Markdown-версии соответствующей страницы** (`/developers/docs/md/...`). Перед платными запросами и при сомнениях сверяй точные поля с **https://api.lumean.app/docs/public-openapi.json**.
5. По мере выполнения работы перечитывай только относящиеся к задаче разделы: ключи/права, шаблоны и голоса, `config-options`, предварительный расчёт чанков, заказы, состояния, повторы чанков, баланс/квоты, хранение и выдача файлов, лимиты и ошибки API.

**Не копируй внутрь навыка полные схемы API и списки моделей. Не угадывай конечные точки.** Используй только официально задокументированные запросы. В частности, голос относится к конфигурации шаблона, текст TTS передаётся как `input_text`, создание заказа асинхронно, а пути из `result.files[]` требуют получения временной ссылки через механизм хранилища.

Справочные страницы по ключевым действиям:
- Шаблоны: https://lumean.app/developers/docs/api/get-templates-browse и https://lumean.app/developers/docs/api/get-templates-config-options
- Предварительный расчёт: https://lumean.app/developers/docs/api/post-orders-chunks-preview
- Статусы и чанки: https://lumean.app/developers/docs/api/get-orders-order и https://lumean.app/developers/docs/api/get-orders-order-items
- Бесплатные технические повторы: https://lumean.app/developers/docs/api/post-orders-order-items-retry-failed
- Скачивание: https://lumean.app/developers/docs/api/post-storage-url
- Служебные файлы и срок хранения: https://lumean.app/developers/docs/guide/files
- Защита от двойной оплаты: https://lumean.app/developers/docs/guide/retries

## 3. Первоначальная настройка доступа

В **корне проекта**, прежде чем начинать работу с Lumean:

1. Если нет `.lumean.env`, создай его с пустой строкой `LUMEAN_API_KEY=`. Если файл существует, не перезаписывай его.
2. Если нет `.gitignore`, создай. Если есть, сохрани все текущие правила и добавь отдельное правило `.lumean.env` (для файла в корне проекта). Не делай дубликатов. Исключи попадание ключа в Git.
3. Если действующего ключа ещё нет, попроси пользователя **прислать ключ Lumean в диалоге**; после получения запиши в `.lumean.env` как `LUMEAN_API_KEY=<ключ>`. При наличии ключа повторно не спрашивай. По возможности ограничь права чтения файла.
4. Используй ключ только для заголовка авторизации `X-API-KEY`, как требует документация. Никогда не выводи ключ в сообщениях, журналах, снимках состояния, командном выводе или списках шаблонов.
5. Если ключ недействителен или у него недостаточно прав, сообщи об этом без повторного запроса секрета там, где он не нужен. Для скачивания **как MP3, так и служебных файлов** необходимо право `orders.download`; для чтения списка файлов — `orders.read`.

Ключ, сообщённый в диалоге, может сохраниться в истории переписки. Не пересылай его третьим сторонам, кроме Lumean.

## 4. Сценарии и вопросы перед запуском

- Обычный сценарий: `voice/text.txt`. Если пользователь указал иной TXT-файл или папку, используй **именно указанный путь**.
- Содержимое каждого `.txt` считай **готовым и неизменяемым**. Нельзя самостоятельно редактировать, исправлять пунктуацию, переставлять, сокращать, перефразировать или добавлять пометки. Текст для озвучки берётся из файла как есть.
- Для массовой генерации пользователь указывает папку/папки либо файлы. Если дана папка без списка, перечисли найденные в ней `.txt` (не считай служебные файлы в скрытой `.cache/` сценариями), назови порядок и **спроси, всё ли верно**. Никаких заказов до ответа. При явно перечисленных файлах сохрани заданный порядок.
- Перед озвучкой проверь готовые MP3 в `<папка_TXT>/output/<имя_TXT_без_расширения>/` с тем же базовым именем и отметками даты/времени. Для одного сценария уточни, не ошибочная ли повторная генерация; при подтверждении новый MP3 добавляется, старый не удаляется.
- При массовой генерации, если часть уже озвучена, **до запуска** сообщи реальные количества и спроси: генерировать все сценарии или только ещё не озвученные. Например: «Найдено 10 сценариев, для 3 уже есть MP3. Озвучивать все 10 или оставшиеся 7?».
- Прочие вопросы, необходимые **для начальной настройки**, задавай до начала заказов. Не прерывай уже идущие независимые задачи ради новых вопросов; см. §11.

## 5. Шаблоны и актуальные модели

**При каждом новом запросе на озвучку** получай через API свежий полный перечень сохранённых шаблонов пользователя **из корня и всех папок, с учётом всех страниц выдачи**. Не полагайся на прошлый список.

- Если шаблонов **не более 10**, выведи пронумерованный перечень прямо в диалоге: название, поставщик (если есть), модель и идентификатор голоса. Если `lumean_templates.txt` уже существует, обнови его актуальными данными, не удаляя.
- Если шаблонов **более 10**, создай или обнови файл **`lumean_templates.txt` в корне проекта**. В нём каждый шаблон получает порядковый номер с 1, название, модель и `voice_id` (можно добавить поставщика для однозначности); разделяй записи **одной пустой строкой**. В диалоге сообщи о файле и попроси выбрать номера. Номера действуют только для текущего списка; при следующем обращении файл обновляется.
- Каждый раз спрашивай, **использовать существующий шаблон или создать новый**. Для существующего шаблона пользователь выбирает номер; используй настоящий `template_id`, полученный через API.
- **Новые шаблоны не удаляй после генерации.** Они сохраняются в Lumean для последующих работ. Не удаляй или не меняй существующий шаблон без прямого указания пользователя.
- При создании нового шаблона сначала получи актуальные **доступные в аккаунте поставщики, модели и параметры** из `GET /usage` и `GET /templates/config-options?service=...`, а голоса — из соответствующего каталога. Кратко перечисли основные настройки, которыми можно управлять голосом, **для каждой доступной модели**. Не перегружай второстепенными полями: объясняй только полезные настройки, реально поддерживаемые выбранной моделью.
- Запроси у пользователя название шаблона, поставщика, модель, `voice_id` и необходимые значения выбранных настроек. **Ничего не придумывай**: все пропущенные необязательные параметры оставляй значениями по умолчанию Lumean. Создай шаблон через API, сохрани `template_id`; шаблон останется доступным для других заказов.
- Для каждого заказа ориентируйся на **MP3 в максимально доступном качестве**, которое разрешает выбранная конфигурация/модель. Если существующий шаблон не может дать требуемый MP3, заранее сообщи и уточни решение; не изменяй сохранённый шаблон молча.

**Массовый режим:** до начала заказов спроси, **один шаблон на все сценарии или отдельный для каждого**. Если выбран второй вариант, заранее запроси номера/настройки шаблонов и соответствия всем сценариям. Допускай как существующие, так и новые шаблоны.

## 6. Проверка стоимости и средств — до любого платного заказа

1. Когда тексты и шаблоны окончательно выбраны, используй бесплатный предварительный расчёт `POST /orders/chunks/preview` **для каждого исходного или дополнительного платного заказа**; при асинхронном расчёте дождись готового результата. Учитывай реальные настройки выбранного шаблона и ограничения (`caps_ok`, число чанков и т. п.).
2. С помощью актуальных разделов по оплате и `GET /subscriptions`, `GET /wallets`, при необходимости `GET /usage`, определи доступную квоту и баланс. Сопоставляй единицы оплаты корректно: **не сравнивай токены с денежной суммой без пересчёта по документации**.
3. Для массовой генерации заранее просчитай **всю совокупность запланированных заказов**, а не каждый отдельно после запуска предыдущего.
4. Если средств недостаточно, **не создавай ни одного платного заказа**. Сообщи о нехватке и вычисли, на сколько **первых подряд сценариев в установленном пользователем порядке** хватает средств. Не сортируй сценарии по цене и не запускай доступную часть без решения пользователя.
5. Если баланс/стоимость невозможно достоверно определить, не считай средств достаточными по догадке и не начинай платную работу до разрешения неопределённости.
6. Проверяй стоимость и средства также **перед каждым новым платным заказом для восстановления ошибочного чанка**.

## 7. Создание заказов, параллельность, наблюдение

- После согласования сценариев, шаблонов и достаточности средств **сразу отправляй заказы без дополнительного подтверждения**.
- При массовой генерации отправляй все согласованные заказы **параллельно**, учитывая реальные ограничения Lumean на одновременно выполняемые операции. Если достигнут лимит параллельности, дождись доступного места и направь оставшиеся заказы, а не теряй их.
- `POST /orders` асинхронен: **сохрани идентификатор каждого заказа** и его связь с конкретным исходным файлом/шаблоном.
- **Каждые 30 секунд** проверяй состояния всех активных заказов через `GET /orders/{order}`; при необходимости читай чанки через `GET /orders/{order}/items`. Не считай `partially_completed` завершением.
- **Во время генерации продолжай другие независимые задачи**, например видеомонтаж или рендер, если агентская среда поддерживает параллельное выполнение. Проверка статусов не должна останавливать их. Если фоновое выполнение не поддерживается, не утверждай, что оно работает: организуй опрос между доступными действиями.
- Обновляй кэш после каждого изменения: создан заказ, изменился статус, обнаружена ошибка, выполнен повтор, скачан чанк и т. д.

## 8. Технические ошибки и восстановление чанков

Учитывай **исходный порядок чанков по `chunk_index` (с нуля)** и действующие успешные версии после повторов. Нельзя путать номера `item_id` и `chunk_index`.

### 8.1. Технический `failed`

1. Определи через API все технически ошибочные чанки, у которых ещё нет успешной замены.
2. Запусти **бесплатный повтор именно этих чанков** внутри того же заказа через `POST /orders/{order}/items/retry-failed`; он не охватывает `policy_flagged`. Повторяй технические фрагменты, пока это разрешает Lumean. Используй возвращаемые причины `skipped` и актуальные статусы; не вызывай повтор бессмысленно при исчерпанном лимите.
3. **Никогда не вызывай `POST /orders/{order}/retry` вместо бесплатного повтора чанков:** он создаёт новый оплачиваемый заказ.
4. Если бесплатные повторы исчерпаны, создавай **новые платные заказы только для неготовых исходных чанков**, а не для полного сценария. Возьми **точный текст каждого проблемного чанка** из официального `GET /orders/{order}/items/{item}/text`; не переписывай его. Для сохранения соответствия исходным позициям допускается отдельный заказ на каждый проблемный чанк.
5. Для каждого оставшегося неготового исходного чанка допускается **не более трёх дополнительных платных попыток генерации** (помимо первоначального заказа; бесплатные повторы внутри каждой попытки не считаются дополнительными платными попытками). Если после третьей оплаченной попытки озвучка этого чанка не появилась — не оплачивай четвёртую, сохрани кэш и сообщи об этом пользователю **после завершения остальных независимых задач**.
6. Отслеживай в кэше сопоставление `исходный chunk_index → заказ/чанк успешной версии`. Если дополнительный заказ разделил исходный фрагмент на несколько частей, сохраняй их внутренний порядок внутри его места в общей дорожке.
7. Чанки с успешными результатами из всех задействованных заказов сохраняй в кэше соответствующей озвучки до окончательной сборки.

### 8.2. Отклонение `policy_flagged`

- **Это не техническая ошибка.** Не передавай такие чанки в `retry-failed` и не создавай для них автоматические платные заказы.
- Получи номер, текст и сведения о проблемном фрагменте через API; ничего не редактируй ни в исходном `.txt`, ни в содержимом чанка.
- Продолжи все доступные независимые задачи, включая рендер видео и работу над остальными озвучками. **Только когда независимая работа закончена**, покажи пользователю проблемный фрагмент и спроси, что делать. До ответа не меняй текст и не оплачивай повтор.

## 9. Готовый MP3 и использование FFmpeg только при необходимости

- Если все чанки конкретного сценария успешно завершились **в рамках одного заказа**, используй **готовый общий MP3, собранный Lumean**. Забери путь из `result.files[]`, получи временную ссылку штатным запросом к хранилищу и скачай файл. Затем обязательно обработай `result.service_files[]` по §9.1. **Не склеивай чанки самостоятельно**, если Lumean уже выдал готовый результат.
- Если успешные чанки пришлось собирать **из разных платных заказов**, скачай отдельные MP3 каждого актуального успешного чанка, восстанови их точный порядок и **собери один MP3 локально средствами FFmpeg**, используя внешний навык:
  **https://github.com/bryanwhl/ffmpeg-video-editor**.
- Служебные файлы каждого заказа при локальной склейке также обработай по §9.1, но **не выдавай их временные метки за синхронизацию локально склеенного MP3**.
- В этом `SKILL.md` **только ссылка** на внешний навык. **Не копируй его файлы, не включай его код в этот навык, не скачивай репозиторий автоматически.** Применяй его, если он установлен/доступен агенту; иначе опирайся на доступные средства FFmpeg и описание по ссылке.
- При склейке учитывай техническую совместимость аудиофрагментов по рекомендациям FFmpeg, но **не проводи отдельную проверку/прослушивание/оценку целостности готового MP3**. Требование пользователя — проверять статусы чанков, а не итоговую аудиодорожку.
- Для каждого исходного TXT создавай **ровно один постоянный каталог результата**: `<папка_TXT>/output/<имя_TXT_без_расширения>/`. Например, для `voice/text.txt` используй `voice/output/text/`. Автоматически создай только отсутствующие каталоги `output/` и `<имя>/`; **не создавай подкаталоги для отдельных заказов, MP3, субтитров, синхронизации или повторных запусков**. Для любого TXT из другой папки аналогично используй `output/` в папке этого TXT.
- Сохраняй итоговый MP3 **непосредственно** в таком каталоге с именем:

  `<имя_сценария_без_.txt> СС-ММ-ЧЧ ДД-ММ-ГГГГ.mp3`

  Здесь `СС-ММ-ЧЧ` — **секунды–минуты–часы**, а не привычные часы–минуты–секунды. Дата и время — местные на момент сохранения. Например: `voice/output/text/text 13-49-14 02-10-2026.mp3`. Для `text2.txt` основа имени — `text2`.
- При повторной генерации **используй тот же каталог** `output/<имя>/`, но новый временной суффикс; никогда не перезаписывай существующий MP3. При совпадении времени добавь уникальный суффикс (например, `-2`) и применяй итоговую основу имени также ко всем сопутствующим файлам (§9.1).

### 9.1. Служебные файлы: субтитры и временные метки (обязательно проверять)

**Цель:** при каждом успешном TTS-заказе вместе с MP3 автоматически сохранять **все реально предоставленные** Lumean служебные файлы: `.srt`, `.vtt`, `.lrc`, файлы выравнивания, `result.json` и другие форматы, если они присутствуют. Не обещай наличие конкретного формата: это зависит от сервиса/модели и результата заказа. Не создавай новые платные заказы лишь ради недостающих файлов синхронизации.

**Получение списка:**

1. После готовности основного результата прочитай свежий `GET /orders/{order}` и извлеки `data.result.service_files`, если поле существует и является массивом строк-путей. Не ищи это поле в `items[]`: в отдельных чанках `service_files` не возвращается. Не путай `result.files[]` (MP3) и `result.service_files[]` (вспомогательные файлы).
2. Если поле отсутствует или массив пуст, **это не ошибка озвучки**. Запиши `not_provided` в отчёт и постоянную сводку, сохрани MP3 без изменений; ничего не генерируй искусственно. Если заказ ещё не готов, не интерпретируй отсутствие поля как окончательный результат.
3. Если `files_expired` либо `retention.files.expired` равен `true`, отметь файлы как недоступные по сроку хранения. Не возобновляй платную озвучку автоматически. Как только файлы появились, скачивай их **сразу**, не откладывая до завершения остальных независимых заказов: у Lumean ограничен срок хранения.

**Скачивание каждого пути `service_files[]` (без дополнительных платных заказов):**

1. Передай точный строковый `path` из ответа заказа в `POST https://api.lumean.app/api/public/storage/url`, JSON-тело `{"path":"<точный путь из service_files[]>"}`, заголовки `X-API-KEY` и `Content-Type: application/json`. У ключа должно быть право `orders.download`.
2. Получи временную ссылку из `data.url` и выполни обычный **HTTPS GET без `X-API-KEY`**. Срок ссылки около часа; запрашивай новую при истечении. Не записывай подписанные URL, ключи и чувствительные заголовки в журналы или файлы состояния.
3. Скачай во временный локальный файл, проверь успешный HTTP-ответ и ненулевой размер, затем переименуй его в конечный файл атомарно. При ошибке не оставляй частичный файл под конечным именем. Применяй правила сетевых повторов из §11 только к безопасным операциям скачивания.
4. **Сохраняй содержимое без преобразования**. Не предполагается, что любой `result.json` содержит именно слова: используй фактическую структуру для последующей синхронизации. Не подменяй отсутствующие субтитры самостоятельно распознанным текстом без отдельного запроса.

**Имена, расположение и соответствие MP3:**

- Все итоговые файлы одной озвучки сохраняй **на одном уровне**, непосредственно в `output/<имя_TXT_без_расширения>/`. Ни `.sync/`, ни `order-*`, ни папок с датой или номером заказа **не создавай**. Промежуточные чанки и состояние обработки остаются только в скрытой рабочей `.cache/` (§10).
- Используй **уникальную основу имени итогового MP3** для всех файлов той же генерации. Например, если MP3 называется `text 13-49-14 02-10-2026.mp3`, каждый служебный файл назови `<основа_MP3>__<исходное_имя_служебного_файла>`; итоговую сводку — `<основа_MP3>__manifest.json`. Сохраняй исходные расширения, не меняй содержимое.
- Имя служебного файла бери только из последнего безопасного компонента пути Lumean: исключи `..`, разделители пути, управляющие символы, служебные имена Windows и недопустимые символы; при отсутствии безопасного имени используй `service-file-<номер>`. При совпадении имён внутри одной генерации добавляй номер (`__2` и т. п.), не перезаписывай никакие уже существующие файлы.
- Для **локальной сборки MP3 из нескольких заказов** добавляй идентификатор исходного заказа в название служебного файла, а не в путь папки: `<основа_MP3>__order-<безопасный_id>__<имя_файла>`. Отмечай соответствующие метки как `source_order_only`: они относятся к отдельному исходному заказу, а не гарантированно ко всему собранному MP3. Не сдвигай отметки наугад.
- Всегда создавай рядом с MP3 отдельную сводку `<основа_MP3>__manifest.json`, даже если Lumean не предоставил служебных файлов. Сохраняй там: `schema_version`, **относительное имя MP3**, способ сборки (`single_order` или `assembled_multi_order`), исходные `order_id`, исходные `service_files`-пути и соответствующие **относительные имена файлов в этой же папке**, статусы скачивания (`downloaded`/`failed`), общий статус (`available`/`not_provided`/`incomplete`/`fragment_only`). Сводка не должна содержать API-ключи и временные URL. При `fragment_only` явно укажи, что синхронизация всего MP3 не подтверждена.
- Если список `service_files` непуст, но некоторые файлы не скачались, MP3 остаётся готовым, а служебные файлы отмечаются `incomplete`. При следующем запуске докачивай **только недостающие файлы этого же MP3**; не перезаписывай готовый звук и не создавай новый платный заказ.
- Если все предоставленные файлы скачаны, отметь их как доступные. Это доказывает загрузку файлов, но не точность временных меток. Не называй `result.json` «таймингами слов», пока его формат не проверен.

**Пример для двух сценариев и одного повторного запуска:**

```text
voice/
├── text.txt
├── text2.txt
├── output/
│   ├── text/
│   │   ├── text 13-49-14 02-10-2026.mp3
│   │   ├── text 13-49-14 02-10-2026__subtitles.srt
│   │   ├── text 13-49-14 02-10-2026__result.json
│   │   ├── text 13-49-14 02-10-2026__manifest.json
│   │   ├── text 09-15-18 03-10-2026.mp3
│   │   └── text 09-15-18 03-10-2026__manifest.json
│   └── text2/
│       ├── text2 20-02-14 02-10-2026.mp3
│       └── text2 20-02-14 02-10-2026__manifest.json
└── .cache/                       # временное состояние, при успехе очищается по §10
```

**Отчёт:** перечисли точные пути MP3, скачанных служебных файлов и их `__manifest.json`. Укажи, относится ли синхронизация ко всему MP3 (`single_order`) либо только к отдельным заказам (`assembled_multi_order`). Не обещай файлы, которых Lumean не вернул.

## 10. Кэш, восстановление работы, безопасная очистка

Для исходного файла `<каталог>/<имя>.txt` используй **точно эти пути**:

- `<каталог>/.cache/<имя>.txt` — машиночитаемый файл состояния (допустим JSON внутри `.txt`);
- `<каталог>/.cache/<имя>/` — скачанные чанки, промежуточные аудиофайлы разных заказов и вспомогательные материалы для их склейки.

Например:

```text
voice/
├── text.txt
├── text2.txt
├── output/
│   ├── text/                    # готовые файлы text.txt без дополнительных папок
│   └── text2/                   # готовые файлы text2.txt
└── .cache/                      # только временные файлы при обработке
    ├── text.txt
    ├── text/                    # исходные чанки и их версии
    ├── text2.txt
    └── text2/
```

В файле состояния храни: точный путь источника; контрольную сумму исходного текста; соответствие выбранного шаблона и его настроек; идентификаторы и состояния **всех** заказов; исходные индексы чанков и их тексты/идентификаторы; сопоставление успешных версий; количество оплаченных попыток; пути сохранённых промежуточных файлов; этап готовности; **список доступных служебных файлов, их состояние скачивания и связь с исходным заказом**. **Ключ API и временные подписанные ссылки здесь не хранить.** Перезаписывай состояние безопасно после значимых изменений, чтобы пережить остановку агента.

При повторном запуске сначала читай существующий кэш и проверяй актуальные статусы заказов. Если итоговый MP3 уже сохранён, проверь соответствующий ему `<основа_MP3>__manifest.json` в `output/<имя_TXT>/` и при необходимости докачай только недостающие служебные файлы по сохранённым `order_id`/путям. **Не создавай новый платный заказ**, если можно продолжить уже начатый или получить недостающий служебный файл.

Если TXT изменился после начала озвучки (контрольная сумма отличается), **не смешивай старую озвучку с новым текстом и не исправляй сценарий сам**. Заверши другие независимые задачи и затем спроси пользователя, что делать. До решения сохраняй существующий кэш.

**Удаление:** только после успешного скачивания/сохранения итогового MP3 **и завершения этапа служебных файлов** конкретной озвучки (все перечисленные файлы скачаны **или** Lumean не предоставил ни одного, постоянная сводка `<основа_MP3>__manifest.json` записана в `output/<имя_TXT>/`) удаляй **только** `<каталог>/.cache/<имя>.txt` и `<каталог>/.cache/<имя>/`. Перед удалением установи, что оба пути принадлежат именно завершённому исходному TXT, лежат в ожидаемой `.cache/` и не являются посторонними/символическими ссылками. **Не удаляй `.cache/` целиком, другие записи, исходные TXT, готовые MP3, служебные файлы, сводки `__manifest.json`, каталоги `output/` или шаблоны Lumean.** При частичной загрузке служебных файлов и иной незавершённой работе кэш сохраняется.

## 11. Ошибки API, защита средств и время вопросов

- При временной ошибке доступа к API делай **до трёх повторных попыток запроса** с учётом документированных `reason`, `Retry-After` и ограничений. Если доступ так и не восстановился, сообщи об ошибке доступа к Lumean и сохрани состояние. Не путай эти сетевые повторы с тремя **платными** попытками из §8.
- **Для запросов, создающих платный заказ, запрещён слепой сетевой повтор.** Если `POST /orders` мог дойти до сервера, но ответ потерялся, сначала проверь существующие заказы через `GET /orders` и состояние кэша. Если исходный заказ найден, продолжай его. Если наличие заказа нельзя достоверно подтвердить или исключить, **не отправляй потенциальный дубликат**, заверши независимые задачи и спроси пользователя.
- При 429 не считай причиной непременно перегрузку: различай частоту запросов, токен-квоту, ограничение подписки, предел параллельности и паузу после отказа по политике. Действуй строго по документации; не делай бессмысленных повторов.
- Не выдавай лимит повторов как разрешение на новые платные заказы без проверки стоимости и баланса по §6.
- **Вопросы пользователю допускаются в двух окнах:**
  1. **В самом начале**, когда собираются обязательные данные (ключ, файлы, повторная озвучка, шаблоны, настройки, решение при недостатке баланса).
  2. **После завершения всех возможных независимых задач** при блокирующих проблемах в процессе (`policy_flagged`, изменение TXT, непонятный статус платного заказа, исчерпание попыток и т. п.).
- Если, например, идёт рендер видео, **не прерывай его вопросом о проблемном чанке**: сначала заверши рендер и все остальные независимые работы. Не останавливай другие озвучки из-за проблемы одной.

## 12. Завершение

После выполнения сообщи, какие конкретно сценарии озвучены, где лежат MP3 и все сопутствующие файлы в каталогах `output/<имя_TXT>/`, какие субтитры и файлы синхронизации реально выдал Lumean, какие файлы не удалось получить и какие сценарии остались незавершёнными. Отдельно отмечай отсутствие `service_files` и отсутствие подтверждённой синхронизации после локальной склейки из разных заказов. Если есть отложенные вопросы, задай их только после окончания независимых задач. Не выдавай незавершённую генерацию за готовый MP3.
